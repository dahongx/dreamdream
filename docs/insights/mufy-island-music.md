# 迁移音乐时保留外观，替换越界机制

技术交接见 [handover](../handover/mufy-island-music.md)。

顶部音乐浮窗和侧边云音乐虽然都播放歌曲，但展开方式、关闭手势、歌单与循环模式不同，不能硬套同一个壳。复用严格配置入口，分开原生控制器，使已有角色不因新角色适配而改变行为。

原站通过父页面注入、持久化整段模板和保存全局对象来保活。迁移只需要同样可见的曲名、艺人、六曲歌单、循环模式与稳定播放，不需要复制这些权限。隔离样式和本平台专属偏好足够，真实播放跨重绘才算功能证据。

外部音频必须区分“选中歌曲”“请求开始”“真实解码播放”。先出现 play 事件不代表已有声音，失败也不应显示永久播放图标。保留失败或未确认项，不能用资源地址还在就当整卡验收完成。

沈砚的 V4 证明“都是播放器”不代表可以删掉其他页：关系和26条指令也是公开交互契约。保留三页和原曲、原文、原模式名，不执行原站 parent 注入程序。安全过滤与局部状态管理也要分开：不能为显示一个页签放松全站隐藏规则，有限组件自己负责非当前页显隐。

输入接口必须区分追加与整稿替换，否则预览的 setDraft 看起来正确，上线接到追加接口却翻倍。光标不能依赖后台页可能延迟的 RAF；和受控输入在同一次提交里恢复，并检查草稿没被用户改掉。验收需取实际渲染后的结果，同时保存早期采样与真正代码问题，不能把两者混为一谈。实现细节见[交接](../handover/mufy-island-music.md)。
