# 把迁移流程变成可交接工作流

接收方验证再发现一处“本机能跑”假象：原测试命令通过源码加载开发依赖，离开仓库就不可运行。候选rc.2把测试也打包，并在中文/空格目录中跑工具和测试。新增blocked验收模板避免把缺省表当完成，保留单卡限制。在线502恢复只解决可访问性，不自动解决视觉/交互和生成验收；交付说明分别表达这些状态。

2026-11-03补充：原先只检查基础转换模块与合成数据，漏掉了批次脚本的后处理链，证明“沿用同一核心”不足以保证流程等效。1.0.0已撤回批量推荐；修复候选强制单卡，需同时完成真实历史数据回归与在线全流程验证，才能允许分发批量使用。真实样本字段回归已通过，测试站502使在线验证仍未通过。

技术入口与版本身份见 [交接文档](../handover/mufy-migration-agent-package.md)。

之前流程分散在脚本、对话、浏览器状态和未提交代码里。其他人仅拿 Git 分支无法复现正在使用的版本，也容易重复导入或互相覆盖发布。此版本把执行技能、转换核心、验收契约、分工及版本校验冻结在同一个包内。

“自查自修”要求 Agent 对缺陷负责到底：观察、留证、修复、实际复验。工具可以拒绝漏项、坏证据、版本不符和明确未解决项，却不能仅靠字段齐全证明作者视觉与语义已经一致。因此不把结构检查通过宣传成整卡自动验收，也不承诺任意组件无需返修。

多人提速依靠互不重叠的卡片分工、单一协调者和统一发布。源角色共享时归同一执行者，但本地档案仍各占一行。新版本或运行环境变化后应重验相关项；历史通过保留为历史，不冒充本次通过。

这次交付是可安装的流程和工具包，未完成当前真实批次验收，也未发布渲染器提案。下一步实际使用需要协调者提供明确名单、授权输入及运行版本，按卡记录真实结果，最终由用户人工抽验。
