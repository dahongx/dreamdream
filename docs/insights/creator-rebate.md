# 产品思考 · 创作者返利

> 技术交接见 [../handover/creator-rebate.md](../handover/creator-rebate.md)。

## 为什么做

寄情的差异化是 **creator 友好**。光有创作工具不够，得让创作者**有理由持续产出好角色**——
返利就是那个理由：把「你的角色被玩、被喜欢」直接兑成收益。对标同类平台的「创作推广收益」，
但砍掉了它的积分等级体系（寄情 v1 明确不做等级）。

## 几个关键取舍

### 1. 独立「创作收益」余额，不直接进消费金币

需求原话是「计入作者账户（金币）」，但我们做成了**独立余额**（`users.creator_earnings`），
不直接进聊天能花的 `gold_balance`。原因：
- 同类平台也是独立「收益余额」+「转换代币」两步（截图佐证）。收益和消费分账，作者能清楚
  看到「平台一共给我发了多少」，不被日常充值/消耗噪音污染。
- 收益支持小数（0.6 / 8.6），而消费金币是整数。混在一起要么丢精度要么全站改小数，代价大。
- 留了未来做「提现 / 转换金币」的口子，不锁死。

### 2. 对话返利只算金币消耗，不算银币

寄情是金币+银币双币，日常聊天大多花银币、签到发的也是银币。若银币也返，作者收益会被
「不花钱的白嫖流量」撑起来，失真。**只认金币消耗** = 只有用户真正付费投入的对话才产生
返利，和「推广收益」的语义对齐——收益应该跟真实付费挂钩。

### 3. 防刷是第一位的设计约束

点赞/收藏/粉丝都能取消再来。如果按「时间窗口数新增行」，作者可以自己反复点赞取消刷金币。
所以用**高水位游标**：只认历史最高水位的净增长，掉下去不倒扣、涨回来不重发。这不是可选优化，
是这类「按社交计数发钱」系统的正确性底线。需求文档也专门点了这条。

### 4. 每天一次批量结算，而非实时

实时返利（每次对话/点赞就发）会让 chat 热路径变重、且难防刷（要维护复杂的实时游标）。
每天早 8 点批量跑一次，既够用（创作者不需要秒级看到收益），又让防刷逻辑简单可测。
代价是��益有最多 24h 延迟——可接受。

## 展示口径的小心思

总览的「四项数据」（总对话/收藏/点赞/粉丝）是**生涯累计规模**，给创作者看盘子多大；
详情流水是**实际进账**，给看钱怎么来的。两者口径不同（前者是展示数、后者按返利规则算），
刻意不强行统一——它们回答的是两个不同问题。

## 没做 / 后置

- **提现 / 转换金币**：先只累加余额，等有真实创作者规模了再做出金链路。
- **收益趋势图 / 按角色筛选明细**：v1 先给流水，够用。
- **等级加成**（同类平台有 Lv1-7 不同返利率）：寄情不做等级，统一费率。
