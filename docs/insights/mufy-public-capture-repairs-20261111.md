# Why imports need component coverage, not just nonempty fields

See the [technical handover](../handover/mufy-public-capture-repairs-20261111.md).

A valid XML file can preserve every character field and still lose the visible experience. In this batch the missing layer was ordinary introduction HTML between frames. Another failure involved complete frame documents combined with a truncated container string. These require independent capture-integrity, structural-coverage and live-browser gates.

Styling also crosses two contracts: the source's authored appearance and the target's accessible controls. Preserve source colors and decoration while retaining the target's functional labels and usable geometry. Reusing a source button's label, width or icon is different from reusing its paint. Likewise, source avatar opt-in should survive migration without replacing the cover or affecting unrelated host bubbles.

Repairs must remain reviewable. Keep original captures, failed experiments, exact owner baselines, narrow candidates and actual rechecks. The rejected rank85 six-floating-widget experiment is useful evidence of a bad derivation, not something to hide or call passed. Preserve each card's successful same-version checks so that a new local repair does not restart the entire audit.

Concurrency is constrained by the user's machine and browser controller. Separate files and preparation can run concurrently; browser work needs explicit ownership and may need a single queue when connections become unstable. More browser requests do not compensate for an unavailable control channel. Report imported, checked, repaired and fully accepted as separate states.

Visual acceptance must check what the browser actually draws. Matching CSS declarations can still select different fallback fonts, and a screenshot saved under a final-looking name can show an earlier repair state. Preserve the failed evidence, verify current glyphs and geometry, and save the corrected image as a new version. This avoids handing the user a convincing screenshot that does not describe the page they will open.

Do not erase an author's styles to hide a parser defect. The rank96 CSS leak was repaired by preserving the complete opening in the existing isolated document path. Source appearance, normal subsequent replies, component interaction and viewport behavior still need their own observed checks; a local renderer test or a successful rule import cannot replace them.

An AI editing draft is not an inspection view of the saved artifact. Owners need a direct, permission-checked route to the rule that is actually running; otherwise agents can mistake preview or subscription switches for proof of its stored contents. Reusing the existing owner editor makes the repair reviewable without introducing another import, hidden-state inspection, or a database shortcut. The local navigation candidate still requires deployed UI verification; it does not itself close the underlying card defect. See section 12 of the [technical handover](../handover/mufy-public-capture-repairs-20261111.md).

Preserving whitespace is part of preserving a creator's appearance. When a paragraph's original blank line disappears during Markdown preparation, changing the imported text hides the real defect. Keep the normal parser's protection against exposed HTML, and preserve the observed source paragraph's text through that parser only in source-rendering mode. Tests must include the actual sanitizer and React renderer, streaming prefixes, literal marker collisions and the old code-leak cases. A passing local integration still needs deployed browser comparison; see section 13 of the [technical handover](../handover/mufy-public-capture-repairs-20261111.md).

Imported source markup carries both author paint and platform defaults. A gradient intended for transparent letters becomes an unreadable block when text clipping is missing; a source36px avatar becomes a large overlay when its utility class was never built. Repair these missing contracts locally from measured source behavior, instead of deleting the decoration or changing the author palette. Keep responsive evidence per card; the same component name does not prove the same breakpoint.

Live streaming and saved reply completeness are separate outcomes. A normal refresh recovered complete replies for ranks68/79 after the live UI had shown errors. Preserve both facts, avoid duplicate paid requests, and continue investigating delivery before claiming the interaction works. See sections15–16 of the [technical handover](../handover/mufy-public-capture-repairs-20261111.md).

Rank79 added a concrete typography lesson: the same mono declaration preserved Latin Consolas while silently switching Chinese from NSimSun to Microsoft JhengHei. Inherited0.32px tracking and different wrapping then added a full20px line to the author note despite equal content width. A source language of `zh-cmn-Hans` and target UI language of `zh-TW` explained an important boundary to investigate, but did not justify changing the user's whole interface language or choosing one Chinese font for every card.

The finite private repair preserved the original text and theme, selected the **actually observed** fallback fonts within the author note and original opening only, and restored measured tracking/wrapping. Owner reload preserved the original prefix; a21-CRLF normalization difference was recorded rather than mistaken for data loss. Actual platform-font inspection subsequently matched the note's Consolas122/NSimSun130/Emoji3 and the opening paragraph's MicrosoftYaHeiUI129, while the note returned to the source349.333px height at380px width. Those observations establish this typography repair; CSS strings alone did not.

Language metadata deserves its own migration contract. A future per-card source-language boundary may help generic fallback, but an explicit TC font stack or a missing SC font resource needs separate treatment. The local `lang` proposal remains unimplemented, and generated authored narration keeps its independent gradient/weight. Preserve these distinctions so a useful local fix does not become an unjustified global substitution or a claim that the card's stream and remaining interactions passed. Exact evidence and boundaries are in section17 of the [technical handover](../handover/mufy-public-capture-repairs-20261111.md).

Rank97 demonstrated that an enabled, correctly loaded theme can still lose its control paint when bare source selectors fall outside the host contract. Measure the source's final appearance, map it only to known equivalent controls, and preserve the host's labels, interaction and active-mask feedback. Static pale input CSS was not the real runtime color; copying it would have created a new white-on-pale defect. A normal owner append and reload verified the finite green-button correction, while live streaming and empty-input scrolling remained explicit failures. See section18 of the technical handover; a successful local theme repair is not whole-card acceptance.

Rank73 separates resource loading from interaction wiring: an audio element can report ready4 and still ignore every click when an earlier cross-frame operation prevented event registration. Keep the original asset, bind the exact public controller and change the smallest incompatible operation. Moving a parent wake listener to the local body also changes event bubbling, so the first-pause regression needs its own check. This repair was saved through the normal owner UI and genuinely played, paused, resumed and sought; remaining title/fold/visual QA was not promoted with it. Exact steps and limitations are in section19 of the technical handover.
