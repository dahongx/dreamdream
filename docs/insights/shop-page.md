# Shop Page — 产品思考

> 技术交接：[../handover/shop-page.md](../handover/shop-page.md)

## 为什么先做月卡而不是直购

竞品对标页（`/tmp/page/1.jpg`）顶层是「月卡 / 直购」二选一，本仓库 v1 只先做月卡有内因：

1. **会员状态是流量入口**：每日签到、聊天扣费、AI 美化包，全都在用 `silver_balance`。一旦把月卡上线，「30 银 / 日 → 90 银 / 日」的差别立刻体感得到，转化路径短。
2. **直购是补丁**：月卡用户也会有「这周聊得多差点银两」的场景，那时直购才有意义。先孤立上线没有飞轮效应。
3. **支付链路一份就够**：月卡 + 直购共用同一套 Stripe / 苹果内购对接，先把月卡 UI 落定再统一接付费，避免做两遍。

所以直购 tab 留了占位 + 「正在准备中」，UI 上保留入口位置，但内容空缺。

## 三档参数为什么不线性

| | 价格 | 立即银两 | 每日银两 |
|---|---|---|---|
| 黄金 | $4.99 | 900 | **90** |
| 铂金 | $9.99 | **6400** | 30 |
| 钻石 | $19.99 | 2700 | 30 |

直觉觉得应该「越贵越多」，但这是从竞品抄来的运营策略 —— 它分别对应三种用户画像：

- **黄金（轻度尝鲜）**：花 5 块钱试个月，主打「每日加成」让他天天打开 app。日活才是关键，瞬时银两少给一点没关系。
- **铂金（决策困难型）**：纠结买不买的人看到 6400 瞬时 + 「立省 70%」标签，会觉得「这档最划算」—— 心理锚点设计，最容易撞到「就买它」。
- **钻石（重度玩家）**：本来就会聊很多、本来就会买，不需要瞬时奖励诱因。$19.99 + 长线权益（无限面具 / 记忆加成）就够。

让数字非线性是有意的运营策略；本仓库照搬，等真有数据再 A/B 调。

## 「无限聊天存档 / 高峰无队列 / 无限面具 / 记忆加成」当前是空头支票

表格里挂的 4 个 boolean 权益，业务侧目前**没有**任何代码读 `users.membership_tier`：

- **聊天存档**：v1 没限制条数
- **高峰队列**：v1 没排队机制
- **人设面具**：当前每个 session 一个 mask 已经够用，没有「面具数量上限」
- **记忆加成**：v1 没有 RAG / context 优先级体系

这些是「先把表格立起来吸引订阅」，业务实装是后置工作。承诺一旦写到 UI 上是产品契约，后端补齐前别让现实差距太大 —— 上线第一周建议：
1. 高峰队列拉一个 feature flag（`MEMBERSHIP_PEAK_QUEUE_ENABLED`），关掉等待但允许埋点
2. 聊天存档加个 50 条上限（普通用户），让权益至少有一个可感知的现实差异
3. 面具 / 记忆等扩展功能上线时再回头扣这块

## 「提升收益」按钮放在每日签到卡上的考虑

签到卡上看到「+提升至 120 银两 / 日」hint，下面立刻一个绿色 CTA —— 这是竞品的钩子：用户每天都会看到当日银两数字，这里是**最高频的转化触点**。所以即使商城页里月卡区已经够明显，这个绿色按钮还是单独留着，滚动到月卡区而不是打开新页 —— 让用户感觉「就在身边」、心理摩擦最小。

## 与 [[../currency-system.md]] 的关系

货币系统是底层（金 / 银两双币 + 每日签到 + 模型扣费 + 美化包扣费），商城是上层（会员状态 + 充值入口）。两层之间约定：

- 商城只往 `silver_balance` 充值（v1 不卖金币）—— 金币是后端为 admin / beta_tester 准备的「人工补贴」字段，对终端用户不暴露入口
- 订阅成功的瞬时奖励走 `currency_transactions(transaction_type='recharge', operator_id=NULL)` —— `operator_id` 留空，因为是「用户自购」不是 admin 操作
- 后续若加月度续期到账银两，约定走 `transaction_type='recharge', note='月卡续期'`，前端的「充值记录」tab（`/me` 钱包）能直接展示
