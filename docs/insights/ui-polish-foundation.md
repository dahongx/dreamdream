# UI Polish Foundation —— 全站美化地基（产品思考）

> 技术交接见 [docs/handover/ui-polish-foundation.md](../handover/ui-polish-foundation.md)。

## 核心判断：碎片化是最大的丑

全站调研（受创作者美化保护的三个区域之外）得出的结论不是「缺装饰」，而是
**同一个设计意图长出了 N 种实现**：四套表单控件规格、五份角色卡复制、三种
tab 视觉、两种空状态词汇、两套确认框、两份大数缩写。用 Mac 设计美学的语言
说 —— 一致性本身就是美感。用户不会说出「这两个输入框 padding 不一样」，但
会模糊地感觉到「这个产品不够精致」。

所以这一批的优先级是**先收口、再装饰**：token 清零、卡片收敛、呼吸点补全，
每一项都让后续任何视觉迭代从「改五处」变成「改一处」。

## 几个具体决策的 why

**货币色独立成 token，而不是复用 accent-gold。** 强调金只用于徽章、特别
标记等稀有状态。金币数字如果也用它，「金色珍贵使用」的原则就被日常余额
稀释了。语义分离让两边都能独立演进。

**rail active 用金色细线。** 这看似违反上一条，其实是 Shell docblock 里
最初的设计意图（"a thin gold underline on the active row"）——「你在这里」
是一种"特别标记"，符合徽章语义。它也是桌面导航缺失反馈的补课：移动端
TabBar 一直有 active 态，桌面没有，同一产品两种导航诚实度。

**呼吸点是产品的心跳。** 「AI 生成/加载用呼吸点」写在 CLAUDE.md 的关键
设计签名里，但实际只覆盖了 chat。补全 auth 提交、付款轮询、admin、上传
之后，用户在任何等待场景看到的都是同一种"活着"的节奏 —— 这比任何单页
装饰更能建立品牌体感。付款回跳那 ~18 秒尤其关键：用户刚把钱交出去，
沉默是最贵的。

**分享落地页是传播杠杆，不只是美化。** 之前分享链接在社交软件里是无封面
的默认卡片 —— 女性向社区的传播主阵地恰恰是微信/QQ 群聊，等于把最强的
获客渠道断在最后一米。落地页同时保住了三件事：爬虫拿 OG、访客看到邀请
卡（转化路径不变）、private 卡门禁与 prompt 资产红线原封不动。

**探索页 hero 的克制。** 「心之所往」四个字的衬线大标题 + 一行题记 +
星点，不加任何交互元素。hero 的作用是给页面定调（"这是一个暗夜书架"），
不是抢注意力 —— 用户的目的地是下面的卡片网格。

## 没做什么、为什么

- **共享表单控件层**：收益最大但体量也最大（要动 2064 行的 CharacterForm），
  塞进这一批会让每个 commit 都不可 review。留给独立一轮。
- **creators 主页的 email 展示、明文密码 localStorage**：一个是隐私暴露面、
  一个是安全问题，都不是"顺手修"的性质 —— 修法涉及产品决策（ID 体系用
  什么代替 email？记住密码功能保不保留？），已上报等决定。
- **对话页/详情页/pack studio 主体**：创作者美化保护区，边界是组件级的
  （详见调研结论），这一批刻意零触碰。
