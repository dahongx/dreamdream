# 回复控件的归属不是消息流的位置

技术实现与发布记录见 [交接说明](../handover/mufy-reply-pet-viewport.md)。

原站回复中的 fixed 控件属于玩家当前视口，而不是某条消息的文档底部。直接放进高度随回复增长的 iframe，会造成控件随消息滚走；照搬 parent.document 注入又会在隔离边界中失效。

因此兼容分两层：保留作者的控件程序和视觉，在独立隔离画布中执行；由平台只管理“最新完成回复”的唯一画布归属和可点击范围。生成中保留旧控件，不用半成品替换。

本次实看还发现，火花控件的共享样式门槛被错误地推广成了所有回复控件的门槛。后续迁移不能把“组件 A 的样式存在”当作“组件 B 可以工作”的前提。

验收必须区分：规则命中、实际节点出现、图片加载、控件可操作、视口位置稳定。缺少其中任何一项，都不能为了批次完成而填“通过”。
# 验收补充：动作成功不等于行为正确

真实手机拖动时，纵向发生移动，但横向被自动宽度变化抵消。验收必须比较请求位移和实际双轴位移，不能只检查坐标是否不同。弹出菜单还需检查三个按钮完整宽度与文字，不能仅证明菜单存在。

无损压缩旧测试备份并校验字节一致后，可以清理其完整重复解包副本；保留压缩包与恢复记录。部署磁盘门槛不能因一个小修复而降低。所有构建、压缩、浏览器等待时间独立记录，不当作 Agent 净工时。

开场验收也要分别确认“容器高度”“可见控件”“媒体实际可用”。高度由 1px 恢复不能推导视频可播放；官方域名放行也不能忽略原卡协议省略地址在 HTTP 测试站上的解析差异。只修获准的准确地址，不能为一个媒体把整个沙箱放开。

公开来源包装与作者组件必须区分。包装脚本中的 parent 引用不一定意味着真实 UI 必须丢弃；反过来，脚本字符串里提到某个 UI ID 也不代表存在真实节点。识别需要已知结构和脚本之外的实际标签，并通过反例测试防止把空脚本、全局样式提成浮层。

公开帧的完整性不能由“抓到了前几个 iframe”或组件数量推导。江峙缺失的资料区就是后续单独公开帧：实际验收要逐块核对可见内容标记和样式，而非只比较卡名、成功导入数量或旧快照。重新解析截取的 body HTML 时，解析器可能把最前面的 style 移到 head；若忽略它，就会出现“文案都在、整个美化消失”的回退。源组件的 head/body 样式要一起保留并看渲染结果。

第三方视频与作者代码不能共享主站通信桥。单独的官方跨域媒体 iframe 只接收已确认的官方地址，不传用户信息或对话能力；框架加载成功与视频源真正就绪仍要分别验证。需要新增权限时明确请求，不以“修复播放器”为理由顺便扩张所有作者组件的权限。

原站没有和寄情一一对应的四个底部按钮时，用户授权的同类控件色调回退应仅继承实测表面，而不是复制原站控件的名称或几何。只采集到模型框时，事实模型也只记录模型框：不能为使用一个完整皮肤接口而虚构正文、标题颜色。发光、真实模型名与功能保持独立，不在颜色补丁中顺便重置。

整批收口改为“先集中检查、修复和本地回归，再统一构建，最后实站复验”。逐个小缺口重复构建既占磁盘，也拉长等待；但不能为了减少构建次数，把依赖新版本的播放、位置、交互行为提前标成通过。发布预检拒绝属于安全护栏生效，和网站本身不可用是两回事；存在其他任务构建时先协调，不删除对方产物或覆盖其版本。

挂件需要输入互动，不等于作者代码应获得真实草稿。保留原作者台词分支时可在宿主只分类长文本/情感/疑问/普通/空，向隔离画布转发固定枚举，再生成固定合成文本触发原分支；原始草稿和历史始终不出宿主。已知原生按钮同理，只转动作名而不转按钮文案。代价是不能宣称任意作者程序通用兼容，必须按真实已知结构识别并保留反例测试。

图片“失效”也需要区分网络、空地址、加载中和永久缺失。一次下载超时不是图片删除证据：江峙同一张原图后续直接打开、下载和真实资料区重载均恢复。保留未改原图有利于后续稳定资源方案，但不能将缓存命中或一张恢复推广为整张卡全媒体通过。折叠栏文字出现与实际能开合也要分开，键盘操作失败不能靠 DOM 的 details 属性替代点击验收。

本地真实浏览器检查仍不可由单元测试替代。五块侧栏此次在真实组件预览中暴露高度循环、捕获运行态图库重复初始化、shadow 丢失继承文字色三类问题；修复应分别落在内联桥、已知生成器重放规范化、来源实测样式继承，不放宽作者代码沙箱。输入挂件要确认宿主重绘后仍是一帧、移动端仍依附输入框；桌面出现头像不能替代手机键盘与实际流式回复的后续 TEST 验收。loopback 开发预览仅加载公开组件程序，不载入完整含私有字段的角色包，也不是对被阻止的官方视频夹具换协议绕行。

“测试页可见图片为零”不是无图卡的证据。简行舟来源有四人图库，旧快照整体漏了后三个公开组件，先前只检查当前已捕获帧得到了假阴性。今后必须将来源组件清单与目标清单逐项匹配，缺失组件优先于图片下载状态；修复以当前 owner UI 基线追加，不能用旧 prepared 覆盖后续修改。保存成功后必须重新导航验呈现和交互。导入通过、局部折叠通过、原站资源失败和整卡通过分开记录。

“按钮已有 host.fillComposer 调用”不代表复制链路可用。此次 inline OpeningSlot 少了父列表→OpeningSlot→RegexIframe 的 draft 回调，而浮动侧栏已接通，因此只验浮动组件会漏掉通用断路。需要穿过实际生产组件的浏览器测试，断言草稿实际变化且发送次数为零。作者 fallbackCopy 使用 execCommand 并保存 success 布尔值也是独立兼容模式，适配时只替换选中 textarea 的复制动作，不替换可见文案，不自动发送，不放宽沙箱。

28卡完整来源清单复查进一步确认，缺项可能藏在资料/关系/第二开场/游玩说明/音乐区，而非正文状态栏。不能按“导入28、回复2轮、若干折叠能点”宣称28卡全验。来源块要唯一编号，逐块映射到目标（正文或浮层），对源站失效和非视觉辅助项给具体证据；零来源块也不能空集合自动通过。文字抽样只做候选诊断，作者更新、用户占位符、懒加载和已在当前owner修好的内容都可能触发差异。

实际操作入口也要按现场适配：仅有开场元件、无对话规则的角色编辑页没有预览侧“对话元件”链接，应展开对应美化包，通过“编辑美化包”链接定位已知 studio。该链接可能开新标签，点击成功不等于当前标签已经导航；及时核对 URL/标题，并关闭已完成自建重复页，避免数十个作者动画/预览并存拖慢后续验收。

来源页自身打不开的确切原图，和迁移丢图必须分列。此次 21 个地址形成两端失败旁证；这能缩小排查范围，但不能用来掩盖真实漏组件。卓序生就同时存在另一类问题：未展开来源侧栏时只得到 2 个内容块，展开后实际有 5 个。采集成功的门槛应包括懒加载内容已呈现；不能靠“导入成功”或“尺寸修小了”收口。新采集器拒绝闭合侧栏的预览框和空 srcdoc，正常展开后再采，不自动运行页面脚本或绕过访问限制。

结构、视觉、隔离是三个不同验收项。原图 48px 的侧边按钮恢复尺寸，仅修复结构壳；五块内容还需要保持原顺序、滚动关系和各自脚本隔离。原站 DOM 中存在面板也不代表桌面截图可见，作者容器的裁切需要实际看图。测试同样不能只看数量：生命周期 fixture 的全局模块 mock 会把真实 iframe 换成假节点，因此真实沙箱边界单独进程验证，避免“测试绿了但测试的不是发布组件”。当前候选不提前标完整通过，也不违反先验好再集中构建的顺序。

此次侧栏采用“静态外壳＋独立执行帧”组合，而非把五段 script 拼进同一 HTML，或为嵌套网页降低 CSP。shadow root 只负责隔离原作者的外壳样式，脚本仍在不透明 iframe。开合状态与程序生命周期分开：首次展开才启动，之后收起不销毁。React 的 innerHTML 更新可能清掉另一个 portal 挂入的节点，必须把清洗后的 markup 对象稳定化，并实际断言五个 iframe 的身份不变；只断言“仍有五个节点”发现不了重建闪烁。

来源懒加载高度也不是设计高度。侧栏中的教程从初始 100px 变到 1014px，若照第一次截图锁死高度，会造出新的滚动差异。应区分作者布局、平台最小视口规则和加载时占位，保留已观测的最小高度/圆角，再让内容自测。空图片亦需看上下文：陈闯的空 src 是未打开的头像预览模态框，不是漏头像；加载不完整但已有自然尺寸的 GIF，也不宜直接列为失效图。

原生宿主片段与独立 srcdoc 必须分开：独立文档不继承宿主主题能避免平台颜色污染，但直接从宿主捕获的表情库依赖作者全局 CSS，套同一规则会变成34张原图裸排、数万像素高度。应保存它实际依赖的公开样式，并只给该片段自包含的显式浮层包络，不能为修一个组件重新向所有独立文档灌入宿主主题。

跨 iframe 的 :focus-within 也有语义差异：宿主输入框得到焦点后，子文档 activeElement 仍可能留在原触发器上。窄范围桥应在该已确认表情库的 window blur 时清掉其内部焦点，再镜像开合；不向作者开放真实父文档。浏览器点击返回成功与真正聚焦是两回事，核对宿主 activeElement / 子元素状态；布局宽度过渡和 focus 消息为异步，不能取动作后第一帧的1px/48px就判最终失败，也不能把未实际收起写成成功。手机面板最终280×500而不是过渡值，证据应取稳定布局。

原生宿主外壳的依赖还包括父子关系，不仅是颜色：黎俨和文攸临的fenced音乐程序本来位于侧栏内部，按代码围栏简单拆成独立文档会把音乐从原生抽屉中抽出去。恢复时应从当前owner提取原节目重绑外壳，不拿最新来源覆盖当前程序、不重复追加一份；各自脚本仍隔离。静态外壳不接受作者脚本、事件或任意行内样式。

焦点型抽屉不应把一次focusout当回复收口。跨不透明iframe与shadow边界时，要区分进入内部程序、普通点击面板外关闭，以及纯父级状态更新。为黑曜抽屉保留明确开合归属，原触发器/关闭遮罩/真实外部焦点负责切换；特定遮罩的display:none被通用安全CSS过滤后，必须在受控组件内显式补回，而不是放开所有作者CSS。帧内合成重绘控件仅用于fixture，不能写入角色包或拿改变过的fixture几何冒充原版像素证据。

验收契约需单列fidelityVerified。所有来源块都找到对应文字，只证明覆盖；还欠原视觉、交互、媒体、生命周期等结论。公开音乐进度若来自真实audio.ontimeupdate，可记录可见进度及代码依据，但不把乐曲标题/“正在播放”占位等同播放成功。任何运行态DOM快照中的进度、生成图库节点等也应与新实例初始化分清，限定已识别模式重放，不能全局清空作者状态。
# 2026-10-29 补充：布局包装层也属于迁移保真

补充交互原则：静态DOM在场、原作者文字在场，都不能证明回调可用。公开导出常将本地函数挂在window.parent，隔离帧中会静默失效；必须实际点击展开、翻页、复制或提取，并验证最终DOM状态。只能为已观测自包含组件做局部window重绑，未知全屏宿主注入程序不能套同一招。好友按钮的运行时闭包不会随outerHTML序列化，原生成器若以children.length早退会留下好看的空按钮；应限定已知列表重建，不可全局清空所有列表。纯文字样本的重复也不能掩盖独立组件缺失，结构身份与功能证据必须一起对账。

独立帧“有Tailwind、有颜色、有按钮”并不代表布局未变。慕行昭音乐帧实测表明，防高度反馈的flow-root会覆盖作者flex；直接恢复flex又可能让平台多加的文档包装层成为收缩项。修复应以来源真实尺寸和当前帧DOM为依据，限定在该组件，不能全站撤销防反馈规则。每次保存后同时验证外层高度、内层宽度、实际媒体推进和原交互，不能只看一种指标。
