# 小按钮也需要迁移契约

技术交接见 [handover](../handover/mufy-source-controls.md)。

同样的快捷符号不代表同样的侧边工具。江峙另有关键词查找胶囊，应把“快捷符号”和“滚动工具”开关拆开，不能为了复用给角色增加原本没有的 Fox 样式。未适配的导航与音乐必须继续保留为未完成项。

保留来源风格不等于直接执行父页面注入。对快捷符号和滚动这种有限动作，可迁移静态样式与明确意图，用平台原生实现，避免作者代码读取输入以外的数据、扫描整页或定时重挂。

验收需要区分“覆盖全文”和“光标选区插入”；还要看回顶是否误滚整个网页。来源三按钮之外平台还有模型/面具/货币等控件，照搬绝对定位会互相覆盖，因此采用独立同风格按钮行，同时保持既有功能和布局。

样式转换必须理解作用域：裸 button 在全站美化中可能代表平台通用按钮，在独立来源组件中却只代表该组件三个按钮。提前加局部锚点可以保留作者色调，不能用平台默认灰白替代后就宣称对齐。

谢闽进一步证明，源码里有完整的 template 不等于入口可见。适配应按有限功能拆开：爱心只负责当前聊天滚动，六条固定指令只作用于手动发送文本，音乐自己的程序只待在隔离帧中。样式清理与宿主布局职责必须同时验证：保住色调还不够，移除 fixed/pointer-events 后若没有有限的信任几何补回，按钮会看似存在却点不到。

验收也要理解作者动画。无缝滚动胶片有离开裁剪区的重复副本，按 DOM 第一项点击可能落在另一个可见人物上。先核对可见区域、实际人物和正文，再判断迁移差异，不能把自动化误点当产品错误，也不能把资源在来源页同样失效误报为迁移丢失。

公开 Shadow DOM 也是实际可见界面的一部分。来源快捷按钮并不在主文档查询结果里，必须正常聚焦输入区并检查公开影子树。字体继承同样属于美化保真：颜色一致不代表原站风格完整，局部来源字体栈不应被平台字体覆盖；修复限制在角色组件根节点，不扩大为平台主题变更。
