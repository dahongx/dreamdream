# 为什么画像采集独立于迁移

对应 [运行手册](../handover/mufy-profile-collector.md)。

后续用户选择“主体先搬，音频没有就没有，差异列单”。应将附加音频缺项与人物主体阻断区分，显式授权后允许省略并记录，而不是全卡淘汰；已可用媒体仍保留，失效原生播放控件不留作损坏UI。音频可选不是图片、身份或样式安全也可忽略，写入成功也不是手机/桌面验收成功。实际首批2张已写入TEST、3张待CSS适配；缺失表应同时展示状态、影响和下一步。

用户随后授权开始首批5张TEST-only迁移实验，阶段已从名单确定推进到真实运行态和迁移准备检查。收藏前5张均重新确认身份，但首次迁移预检全部阻断；资源访问、体积限制和CSS适配属于迁移能力缺口，不能伪装为身份筛选失败，也不应悄悄换5张容易卡来提高成功率。正常补抓可恢复部分媒体，原引用仍失败就留阻断项；不能删音频、绕过样式安全限制或编造目标已验收。运行态只保留角色来源字段，不应附带当前用户面具或会话信息；程序运行计时与用户停留、首次开发必须分开。

当前用户只要求先确定100角色，停止在筛选过程中穿插迁移预检。把热门候选池扩至500，从后续可对应角色补位，比反复维护一个证据不足的旧100名单更符合目标。实际核对310张得到100个对应角色；依据是有主角关联的长开场正文一致或至少两段非指令人物事实一致，而非同名、模板欢迎词或“年龄相同”。名单和迁移准备是两个不同完成状态；原20张预检历史不能覆盖已确定100角色的当前阶段。

更深入的实际预检发现两类不能混淆的问题：档案索引主角错误需要换关联；合法源卡把音频/表情库写在样式字段里，需要修适配，不能因此淘汰角色。开场正文相同而HTML不同可以单独同步公开渲染；原文仍保留指纹。阶段数量允许随证据和规则修订，但报告必须保留规则版本并明确“采集、优先预检、dry-run无阻断、成品完成”的不同含义。

用户选择可用/可同步即保留后，应把“隐藏Prompt最新版不可证明”从全体拒绝理由改成版本标注，不应继续人为阻断所有候选。底稿保留用户提供的档案，公开开场/美化分开同步；人物、关系、世界观变化仍需明确核对。优先预检名单不等于验收或迁移完成，缺年龄或公开开场不同不自动等于废卡。“新增18岁番外”被误当“18岁版本”的规则已收窄，不能靠宽泛关键词制造淘汰。

真实取证进一步说明：一个年龄字段可能与作者小剧场不一致，空creatorName也不等于换作者。报告应保留疑点，不能把探针字段缺失直接升级成卡片事实。公开开场可以逐字比对，但无法从公开详情证明隐藏Prompt全文相同；必须让用户选择本地档案版本或严格同版本标准，不能静默替用户放宽。“100个读取成功”“100个名单补齐”“100个验收通过”是三个不同计数，补位后证据必须按固定roleId/Prompt指纹重新绑定。

本轮发现热度去重会保留错误的本地全文命中关联：宴雎被关联到“本人”。名称防重不是来源核验，29项测试通过也只证明测试覆盖的规则，不证明实际100张卡准确。修正后明显不相容的关联自动剔除并补位；仅有名字线索的进入待核对而非用户已确认或迁移已就绪。实验草稿在逐卡身份、版本、目标不存在证据齐全前不得接入执行编排。

选卡是迁移Agent的前置阶段：不能从旧Top100删几张就交付不足100，也不能先搬再发现目标已有。应读取测试库存，从完整候选排序中排除再补位，留排除证据。测试服同名只支持保守防重，不足以证明源卡身份；括号版本及改名角色必须明确残余风险。将筛选与身份/版本核对分成两个关卡，既能给出热度优先的100个候选，也不让模糊搜索错误关联的Prompt进入迁移。

采集回答的是“找到了哪些候选、热度多少、来源可否对应”；迁移回答的是“这张已确认卡能否在测试服完整复现”。合在一个自动写库循环里，会让高热度同名卡绕过身份核对。程今越的总裁/新生差异正说明名字不足以证明对应。

本地档案用稳定key和Prompt SHA256建立身份。一个名字可关联多个线上候选，不能把它们的热度相加，也不能自动选择最火者。候选榜与确认榜必须分开；确认之后只给迁移Agent角色ID、原始Prompt和证据，不把画像采集成功当作整卡搬完。

最初逐张操作页面既慢，又会被页面默认筛选影响。真实请求中 `showNsfw:false` 导致“成功空结果”仅能说明当时筛选下没有命中。全量模块显式记录查询范围、分页完成度、时间和失败，缺失保留null，不用0填平。

可复用的关键是断点和可追溯性，而不是承诺永远不断线。登录、限流、来源下架、机器休眠都是外部条件；页面IndexedDB加本地任务状态保证恢复后不重复统计。权限只来自现有登录，不收账号密码、不导出token、不操作生产服务器。

持续迭代必须落实到兼容规则与回归测试；这不是自主学习系统。运行日志用于测量真实采集成本，开发时间单列，不能把第一次系统搭建工时算到每一张角色上。
# 监控补齐记录

长任务必须同时具备执行器与监督者：页面检查点只能保护数据，不能保证异常被人看见。2026-10-13出现AUTH_REQUIRED后无人提醒的缺口，已通过当前聊天每5分钟巡检和独立monitor状态去重补齐。正常无进展超过10分钟、首次暂停、恢复、完成才通知；通知延迟受应用运行和调度影响，不宣称实时。新的监督机制只处理本地画像任务，不扩大服务器写入权限。
