# 迁移入口的完整性

2026-10-22 验收纠错：可展开、有正文不等于状态栏美化正确。崔稚玉漏采了整块公开 CSS，却因交互可用被过早标为核心通过。今后须同时证明折叠态背景/内边距、展开布局、手机宽度及下一轮实际生成仍继承样式；准备流程发现 classed disclosure 没有对应 CSS 必须停下来补采。将莱的引用修复明确标为迁移兼容，不伪称作者原规则，不改变模型指导。结束星号缺失与样式丢失分别记录，不能用界面修好了掩盖模型完整性未满足。

后续闭环已实际完成：不能把“模型没遵守”当成停止修复的理由。保留作者要求和原始档案，在迁移副本中消解宿主停止规则的顺序歧义，并给出足够短、明确的实际结尾格式。首版提醒失败、第二版结尾范式连续两轮通过，证明修复应以生成结果检验，不能以“保存了指令”检验。只有完成标记但缺结构仍然失败；只有完整结构但少作者要求的标记也仍然失败。最后以连续两条不同真实生成、手机桌面开合复测和原文证据对账关闭本版试迁移，用户负责最终体验检查，而不是替 Agent 做逐卡修复。最新入口见 [交接收尾](../handover/mufy-normal-ui-import.md)。

首批五卡的浏览器验收结束，并不意味着下一批所有输入都已具备可执行的导入路径。本次发现网页导入忽略明文小剧场，若仅依据「角色创建成功」判断迁移成功，会把组件缺失推给用户返修。

迁移应分别记录原文、开场组件、全局样式和后续回复规则。只读公开设置看到规则名称，不等于已取得其实现；渲染页面保存的 HTML 也应标明来自公开 DOM，不能伪装成原始规则接口响应。

当前先补全现有网页导入明文组件的能力，并保留输入指纹和逐阶段耗时。未部署、未导入和未验收的状态必须各自准确记录。技术说明见 [正常网页导入交接](../handover/mufy-normal-ui-import.md)。

新入口还暴露了另一条遗漏：旧布局兼容开关只认 rendered-opening 规则，正常 XML 导入虽保留组件，却没有那条旧规则。陈妄手机端开场的两个折叠框因 flex shrink-wrap 变窄，记忆区仍满宽。修复必须识别真实的离线组件适配标记，不能伪造一条源站规则来骗过开关。普通卡保持原路径；首批旧入口仍识别原规则。准备脚本增加适配标记检查，已有导入回执时拒绝重复准备覆盖检查点。

五卡核心试测与完整来源一致性是不同门槛。本轮完成十次真实回复及双尺寸检查，也补齐了实际头像；但不把尚未确认的结束标记、细小格式差异、全部媒体和特殊分支统称为通过。交付记录显式保留 coreTrialPassed 和 strictSourceFidelityAccepted 两个数字，避免下一轮拿局部通过冒充所有功能完成。
# 2026-10-22：完整输出不等于完整迁移

用户逐项对照发现的 scene、眼睛、台词头像、侧边记忆和完成星号，属于同一个验收缺口：以“宿主能渲染”代替“来源实际怎么显示”。内部格式合同只能校验输出是否完整，不能要求用户看到原站没有的检查标记。后续关闭必须同时满足原始输出合同与来源显示合同，不能互相替代。
