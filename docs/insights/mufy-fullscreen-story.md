# 全屏组件不能困在小画布，也不能开放父页面

技术交接见[全屏动效适配](../handover/mufy-fullscreen-story.md)。

来源沈砚的入口是行内装饰，点击却会向整页注入人物动效。只把 parent 引用改成本窗口会让原设计困在小 iframe；直接开放父页面则越过作者组件的安全边界。

选择分离展示归属：入口留在原位置，由平台负责独立全视口容器；来源原程序只在不透明画布内部运行。平台只接收绑定窗口的关闭请求，不提供聊天、账号或发送能力。这样保留来源视觉、定时和点击顺序，而不是另画一套相似动画。

通过标准必须包括三幕内容、过渡、自然退出、重开、关闭后输入和重复渲染稳定性。截图必须等面板真实可见，不能把动画初始 opacity=0 判为内容缺失，也不能把只见首帧判为完成。当前仍是未发布候选，不代表本批整卡验收完成。

## 2026-10-31：点击前像，不代表点击后像

江之余的人物封面在两站都存在，但真正点开才发现：测试站只剩小框弹层，原关闭也失效。资料折叠、音乐或按钮样式的既有通过，都不能替代另一个独立入口的生命周期检查。

全屏归属之外，还要恢复来源父页面的继承契约。原站弹层的衬线深红字、1.8 行高及细滚动条，与小 iframe 自身的字体/白字默认值不同。保留原程序并不自动保留最终视觉；应先量真实结果，再限定修复范围，而不是开放真实父文档或把全站重新换肤。当前候选只验证本地，整批上线验收仍未完成，详见[技术交接](../handover/mufy-fullscreen-story.md)。
