# Inventory completeness before fidelity

A four-component opening can match while an additional global player is entirely absent from the inventory-to-target mapping. Counting only the opening root creates a false sense of completeness and leaves the user to discover missing tools.

The source inventory is the base: every captured root and frame needs an explicit disposition. A zero-height frame may be the launcher of visible parent UI. Its geometry alone cannot justify dropping it. Missing mapping remains a concrete repair task; it is not silently accepted, and it is not automatically a proven missing target feature.

The current preparation guard stops unsupported multi-root conversion early. A finite native adapter can later restore the author's behavior without replaying arbitrary parent DOM programs. Existing successful interaction evidence remains valid for the same component and runtime; only the uncovered items are added to the queue.
