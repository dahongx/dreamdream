# Mufy 样式隔离与验收边界

对应[复验记录](../handover/mufy-visual-recheck-2026-10-12.md)。

余斯是的浅底手机组件使用通用根变量，合并后覆盖宿主强调文字颜色。迁移时必须同时改写组件变量声明和引用，不可把所有文字强制改白。原版强调文字的蓝灰细线有效，而块级叙述背景需要分别处理，不能整组删除。

本轮已加入变量隔离及强调规则回归测试。测试通过只证明这两个代码路径，不证明整卡视觉一致。运行态验收还需要加入强调色和背景对照，并覆盖同尺寸手机视口、浮层动画完成态、展开/收起、图片尺寸和媒体交互。没有测过的角色或状态必须标记未验，不能由容器存在推断组件完整可用。

追加经验：桌面提示条应测量聊天列而非窗口，手机规则保持独立；横向溢出应比较 documentElement.scrollWidth 与 clientWidth（不能只和 innerWidth 比，后者包含滚动条宽度）；播放器必须观察时长加载和 currentTime 对应的进度走动，并检查切歌，暂停图标并非播放成功证据。可获取的原音频应迁入目标资源库，不能替换成别的歌曲；来源失效、无交互脚本的组件必须单列待核对。

沈知衡补验：角色资料检索必须覆盖仓库根目录的历史导出，不能只搜最近批次目录。较新快照可只有外观，较旧导出可能有有效歌单；跨版本合并需保留来源版本并获得用户明确授权。不能用静态曲名猜音源，也不能把 HTTP 200 的 HTML 当 MP3。恢复监听脚本必须进入同一个 floating iframe。此次按用户授权将旧版 15 个有效音源接回当前外观，1 个失效源明确记录；该适配器只在显式提供歌单时工作，不自动为别的卡编造音源。

最终对照纠正：旧归档与当前 Mufy 冲突时，应先查看当前实际运行页。公仪晢当前原版是 16 首，与测试服一致；旧资料 6 首不能证明错搬。喻承砚 MEMORY 与 INJECT 的局部重叠在原版也能复现，不能只凭测试服截图归为迁移缺陷。验收记录应标明“确认缺陷／来源差异／原版行为”，并撤回已经被新证据否定的问题。
