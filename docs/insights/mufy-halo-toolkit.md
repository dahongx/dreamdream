# 工具箱不能按“源码存在”验收

[实现与未完成事项](../handover/mufy-halo-toolkit.md)。

林叙的 Halo Ball 把音乐、表情、指令、画板组合在一个悬浮入口里。源模板在目标开场中存在，但父页面注入被隔离，所以入口完全不出现。判断迁移完整性必须查用户看得到、点得到的入口，而不是只比对文本。

继续保留作者的发光球与原色调，不套平台主题。兼容问题按明确功能建立本地控制器，源数据与程序分离；不能为了恢复一个球而授予整个作者程序访问平台 DOM、账户存储或发送接口。

本轮仍是未发布版本，不是整卡交付。现已补齐画板、指令增删/模式/持久化、手动发送前作用域拼接，并用真实浏览器和截图验证其一部分行为。不能用“实现了”替代 TEST 验收，也不能用合成触摸替代物理手机。来源登录、原媒体不可用、当前 Edge 文件选择权限、大段源码编辑超时分别记录，不能混写成“网站被拦”或“来源已下架”。

多次回复重绘后的浮动控件必须保持身份、展开状态与播放进度；绘画工具条不只首次摆得下，还必须在拖动、取消和视口变化后可达。标签也属于状态：看见的分类已变、无障碍名称未变，同样是交互缺陷。
# 来源继承也属于迁移契约

工具箱即使自己的 CSS 已保留，未显式声明的文字仍可能继承平台色调。应把原站公开实测的继承根约束在该角色惰性壳内，而不是修改全站主题。行高保留比例语义，避免小字号元素继承大字号的固定像素行高。浏览器实测和动态效果须分开记录；脉动不同阶段的截图差异不能误判为色彩回归。
