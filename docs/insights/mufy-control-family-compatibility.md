# 不能让兼容快照压过风格同步

实现与证据见 [handover](../handover/mufy-control-family-compatibility.md)。

按钮底色不同不一定是作者设计。旧的计算样式快照可能优先级过高，压过后来增加的同功能控件适配。背景和文字还可能被不同规则控制：第一轮底色同步后出现白底浅字，必须继续真实复查，不能凭保存成功交付。

后备快照应低于明确的按钮家族规则，家族前景色则要与功能文字保护协作。修复不能重新复制来源伪文字，也不应牺牲模型名称、菜单语义和可操作性。中间失败与最终成功分别保存，方便解释何时改变、为什么不是回退。

同样，主文档里的组件与独立iframe的继承环境并不相同。丢失border-box会制造微小但可见的横向滚动条；正确做法是恢复已实测的局部继承契约，不能全局隐藏溢出。来源证明、适配范围和排除完整文档的条件都必须写入回归检查。
