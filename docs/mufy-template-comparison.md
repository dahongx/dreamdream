## 四、核心差异：为什么 Mufy 模板更稳定？

### 原版实现（黎衡、沈亦寒）

```
提示词：请生成以下内容
- 场景头（时间、地点、人物、环境、氛围）
- 正文（对话、叙述）
- 状态栏（4个折叠模块，每个150-300字）

模型：
→ 自己理解提示词
→ 自己组织格式
→ 自己决定写多少
→ 可能写得很好，也可能敷衍
```

**结果**：
- 长度波动：2000-3500 字符
- 稳定性：依赖模型状态
- 第1轮：详细（150字）
- 第10轮：可能敷衍（"正常"、"无"）
- 第15轮：可能偏离人设

---

### Mufy 模板实现（黎衡1、沈亦寒1）

```
固定模板：
<details class="sb">
    <summary>＞ᴗoಣ</summary>
    时间：ai填充时间<br>
    地点：ai填充地点<br>
    衣着：ai填充衣着<br>
    动作：ai填充动作<br>
    ...
</details>

模型：
→ 只负责填"ai填充"部分
→ HTML结构是固定的
→ 不需要组织格式
→ 不会忘记某个字段
```

**结果**：
- 长度稳定：模板本身1900-5600字符 + AI填充内容
- 稳定性：HTML结构永远正确
- 第1轮：详细
- 第10轮：仍然详细（框架强制）
- 第15轮：框架保证不遗漏

## 七、关键发现总结

### ✅ 所有 Mufy 热门卡都用固定模板

- 83张卡中，80%使用三大模板之一
- 不是"每个角色完全独立一套"
- 而是"选择一种模板 + 微调人物专属模块"

### ✅ 固定模板解决了所有当前问题

- 长度稳定：模板本身就有足够字符数
- 格式稳定：HTML结构不会错
- 信息密度稳定：即使AI偷懒，框架也在
- 人物声音稳定：附属模块体现人物特点

### ✅ 实现难度：简单

- 不需要写代码
- 只需要改 outputSetting
- 2-4 小时 / 张卡

### ✅ 这才是真正"学到精髓"

- 之前的差距：底层实现方式就不同
- 现在的方案：完全对齐 Mufy 的技术架构
- 预期结果：新卡稳定性接近 Mufy 热门卡
