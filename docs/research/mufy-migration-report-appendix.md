更新日期：2026 年 10 月 15 日。本附录配套[实验主报告](./mufy-migration-experiment-report.md)，保留可追溯过程及案例，不代替主报告的当前结论。所有时间按北京时间理解；原始 JSON 日志的 UTC 时间需要加 8 小时。

## 一 阶段记录与输入输出

| 阶段 | 输入与操作 | 合格标准 | 输出与实测结果 |

## 二 筛选标准及规则变化

### 最终身份通过标准

1. 本地档案名字和人物设定中的主角要对应；线上详情必须绑定明确的角色 ID。
2. 排除已经有测试库存对应证据的卡片；对本地底稿保存和重读 SHA256。
3. 86 个通过公开开场长正文对应：去掉 HTML、脚本、样式，进行 Unicode 和空白归一化；长正文不少于 100 字符，相同且包含主角。这不是要求两侧 HTML 逐字相同。
4. 14 个通过人物事实对应：从本地人物设定提取 45 至 400 字符的非指令型段落，至少两段出现在公开人物资料中，并有主角对应；该分支还要求已知基础年龄不冲突。
5. 开场对应分支出现基础年龄冲突时保留差异标记，不直接否定角色；迁移按用户授权的底稿取值，公开来源另存。

“至少两段相同”指上述归一化后文本，不应汇报成整份隐藏 Prompt 已逐字匹配。

### 重要政策变化

| 原要求或发现 | 最终处理 | 保持不变的边界 |
|---|---|---|
| 线上隐藏 Prompt 最新版本无法取得 | 经用户授权，以本地档案为底稿，同步有来源的公开内容 | 不猜改隐藏设定，不混不同人物或人生版本 |
| 同名或年龄相同，但人物关系证据不充分 | 暂不选，展示差异并继续从后续候选补位 | 不将“证据不足”宣称为“确定错卡” |
| 年龄基础元数据与底稿或公开人物介绍不一致 | 核对本人年龄线索；本批已授权使用底稿年龄 | 不将亲属、历史阶段或其他人物的年龄当本人的证据 |
| 媒体暂时无法取得或无法上传 | 用户允许图片、音频后补，主体迁移继续 | 不造假资源，不绕过认证，不把坏播放器标成可播放 |
| 样式或宿主组件不兼容 | 修通用适配、保留非可移植装饰差异，再验收 | 不放宽安全过滤，不靠删除主体内容骗过检查 |

最终 500 候选池里，100 确认、204 待确认、6 索引错配、190 未读。历史人工复核排除、初筛排除和最终决策可能重叠，不能合并相加为“筛掉多少张错卡”。

## 三 具体失败案例

### 身份和版本案例

| 案例 | 两侧事实或问题 | 决策与原因 |
|---|---|---|
| 程今越 | 本地底稿为 40 岁、今朝集团创始人兼 CEO；候选公开开场为大学开学和同学关系，基础年龄 20 岁 | 属于不同人生阶段的关联，不把 CEO 底稿套到校园版；排除此关联并补位。不能据此证明改写一定出自原作者 |
| 凌曜 | 本地为 18 岁集英高中高三学生；公开小剧场为 23 岁京州大学大三 | 年龄之外，学校和身份阶段也不对应；排除当前关联，不当成单纯年龄字段同步 |
| 玉雪融 | 档案索引叫玉雪融，人物设定主角为应逐星 | 本地索引与设定错配；排除错误关联，后续需要正确底稿才能重新候选 |
| 顾知裴的标题番外 | 标题新增“18 岁番外”曾被理解为整张主卡改成 18 岁 | 纠正误排并加回归；新增番外不自动等于主卡人物年龄变化 |

### 迁移和交互案例

| 问题 | 失败表现 | 修复结果或当前处置 |

| 首次严格准备检查 | 五卡均未通过，卡在媒体或样式兼容；不代表五卡人物都不正确 | 用户允许媒体后补后继续主体迁移；身份和 TEST-only 保护保留 |
| 宋怀远资源上传 | 部分音频不可访问；一张 GIF 和一个音频即使已取到，仍不符合目标存储上传限制 | 按授权列媒体缺项，不调整存储安全权限；无扩展名资源用已知 MIME 识别 |

| 风满楼手机卡片 | 内嵌卡片宽度加上 padding 后文字裁切 | 手机盒模型适配；展开卡片适应约 354px 内容列，内层无横向溢出 |
| 风满楼内嵌高度 | 展开后 iframe 高度只增不减，约 11,111px，而收起后正文约 2,327px，造成空白 | 改按真实正文重新上报高度；实测 iframe 2,328px，正文约 2,327.417px |
| 测试服 SSH 中断 | 在连接握手阶段被服务器关闭，部分更新中断 | 先核对已落库 ID，不盲目重复创建；连接恢复后批量传输、复用一次远端执行。未修改认证、防火墙或正式服 |
| 报告回传冲突 | 落库已成功，但两个回传使用相同本地文件导致读取失败 | 每轮采用独立目录与文件；将落库结果和回传结果分开，不以进程退出码单独判迁移成功 |

历史上盛则言和邱石的样式字段夹带音频或表情 HTML，迁移检查曾阻断；当时保留角色等待通用适配，不靠删内容放行。这两张不属于当前已迁入的五张，不能写成已经在本批修复完成。

### 计时口径与历史修正

- 全量观察耗时从 10,839 个已保存搜索观察的 `elapsedMs` 相加，得到 26,465,619.4ms。含配置等待和网络，不含用户暂停；早期失败被重试覆盖，因此是已保存观察的下界。
- 全量项目墙钟为 61,742,170ms，包含开发、登录暂停和浏览器不可用，不能叫“纯采集耗时”。
- 身份阶段本地命令 62,704ms，是全量搜索结束后至最终身份名单生成之间 `operations.jsonl` 已结束命令的小计；不是所有筛选操作。
- 旧汇报约 9 分钟、首次五卡約 47 秒等数字是阶段小计或下界，不作完整 Agent 工时结论。最新检查文件重跑后数字也会变化，不能覆盖历史意义。
- 第一修复计时阶段共有 22 条记录，直接累计 306,587.009ms；其中早期业务失败可能被脚本捕获而进程退出码仍为 0，必须结合写入报告判断成功。
- 后续补修共有 22 条记录，程序工作量累计 1,176,652.673ms，合并重叠时间区间后为 1,095,724ms。未包裹的开发、阅读及部分浏览器点击未计入，不能把差值简单叫“思考时间”。
- 后续补修有 7 条带回放标签的程序事件：1 次在本地映射保护前停止，另外 6 次进入远端更新流程，其中首次逐卡回放中断、一次批量回传失败。实际问题修复次数、命令次数和单卡成功率不是同一个指标；保留事件，后续另定统一统计方式。

### 人工介入与自动化说明

可以确认的人类介入类型包括：提供本地压缩包、正常登录与恢复登录、明确本地版本与媒体后补政策、要求继续修复，以及当前用户成品检查。用户没有被要求手工编写迁移代码或逐字段录入五卡。

没有完整记录全部登录、确认和催促次数，不能汇报“整个项目人工介入 0 次”或凭聊天间隔换算人工分钟数。早期单轮报告中的“人工介入 0”仅指该次来源补抓没有请用户手改资料，不代表全项目。
