# 技术交接 — UI 文案收敛与展示边界

> 产品思考见 [insights/ui-copy-system.md](../insights/ui-copy-system.md)。

## 目标

整站 UI 只向当前受众展示完成任务所需的信息。页面标题负责定调，字段帮助负责正确填写，
确认框负责说明后果；数据库字段、渲染协议、平台内部立场和部署步骤不进入普通用户界面。

这次改造同时修复了审校过程中发现的事实与数据边界问题。文案不能承诺代码没有实现的权益，
也不能用一句“仅 owner 可见”代替真正的查询权限。

## 展示层级

1. 核心页面保留一个 `hero-title` H1，继续遵守 `DESIGN.md` 的大号衬线标题签名。
2. eyebrow 只有在提供 H1 没有的信息时才出现；重复品牌名或页面类别时删除。
3. tab、字段名、按钮已经能说明用途时，不再追加副标题或操作教学。
4. 空状态的 `hint` 可选。优先使用短标题和真实 CTA，不强制写第二层解释。
5. 专业创作语法留在字段附近或“技术详情”中；玩家页面不出现内部协议和数据模型。

## 关键事实边界

### 月卡与付款

- 月卡是一次性购买 30 天，不是自动续费订阅。
- 前端回跳只显示“正在确认”，订单状态为 `paid` 后才能显示支付成功。
- 商城只展示已有消费端支持的权益。新增权益时先实现判断，再补售卖文案。
- 普通用户余额不足的恢复入口是 `/shop`，不是联系群管理员。

相关技术链路仍以 [stripe-payments.md](./stripe-payments.md) 为准。

### 开场组件源码

开场组件是 creator-private 资产。角色创作页只加载角色作者自己美化包中的组件：

- `filterOwnerOpeningPacks()` 在页面组装阶段排除其他作者的公开包。
- `listOwnedPackOpeningComponents()` 在 SQL 查询中再次校验 `owner_user_id`。
- 包详情和 Studio 先完成 owner 校验，再查询并传递完整组件内容。

不要重新引入“先查全部组件，再在 Client Component 里隐藏”的写法。Server Component 传给
Client Component 的 props 会进入 RSC payload，隐藏 UI 不等于保护源码。

### 公开创作者资料

公开主页使用 `username` 作为账号标识，不查询或展示邮箱。新增公开资料字段时仍按公开白名单
审查，不要因为数据已在 `users` 表中就默认可展示。

### 破坏性操作

确认框描述实际用户后果，不描述数据库实现。角色删除会连带删除全部会话、消息，以及删除后
不再被其他角色使用的本人私有美化包；文案必须覆盖这部分永久损失。

## 术语表

| 用户概念 | 统一用语 | 避免使用 |
|---|---|---|
| 进入账号 | 登录 | 登入 |
| 主要对话区域 | 聊天 | 会话（作为导航名） |
| 作者工作入口 | 创作 | 创建、管理后台式标题 |
| 购买 30 天权益 | 购买月卡、再次购买 | 订阅、续费、`/月` |
| 货币 | 金币、银币、余额 | 口粮、银两、货币流水 |
| 角色使用美化包 | 添加到角色、移除 | 订阅、解绑 |
| 对话组件开关 | 玩家可关闭、始终启用 | 玩家可见、creator 私有 |
| 生成异常 | 回复没有生成完整 | 安全策略拦截 |

后台可以保留模型、token 和成本等专业词，但不展示 `transaction_type`、迁移编号等数据库或
部署细节。DebugPanel 受开发者权限保护，system prompt、latency、tokens 等信息不做玩家化改写。

## i18n 维护

- 字典结构以 `src/i18n/types.ts` 为契约。
- 修改任何可见文案时同步 `zh.ts`、`zh-TW.ts`、`en.ts`、`ja-JP.ts`、`th-TH.ts`。
- `i18n-dictionaries.test.ts` 只保证键与占位符同构，不能保证语义一致；涉及付款、权限和删除时
  必须人工核对每种语言。
- 删除 UI 后同步删除已无调用的字典键，避免旧文案以后被重新挂回页面。

## 验证

```bash
bun run typecheck
bun run lint
bun test
bun run build
```

页面烟雾验证至少覆盖 `/explore`、认证页、`/create`、角色编辑、聊天、`/shop`、`/settings`
和美化包 Studio。重点检查移动端是否因删除副标题留下异常空白，以及危险确认和付款状态是否仍有
明确下一步。
