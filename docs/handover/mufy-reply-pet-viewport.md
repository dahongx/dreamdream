# Mufy GP 回复桌宠：固定视口兼容

产品依据见 [产品说明](../insights/mufy-reply-pet-viewport.md)。本项仅发布到 8091 测试站，不涉及数据库、正式站或角色原始设定。

## 已定位的两层问题

- 原站 `censy-gu-pet-host` 程序通过 `const pWin = window.parent` 注入父文档。普通隔离回复框架禁止跨域访问，因此 GP 规则命中不代表桌宠出现。
- `MessageBubble` 的侧栏入口历史上要求火花/记忆共享 CSS 非空。GP 自带样式，不能用另一个组件的 CSS 存在与否决定其挂载。

## 边界

`MufyReplyPet` 只从已经渲染的 iframe segment 提取已识别的完整 GP 模板，普通 HTML segment 不会升级为程序。保留作者脚本与控件样式，在 `RegexIframe` 已有的 `parentShim` 中执行；仍为 `sandbox="allow-scripts"`，没有 `allow-same-origin`，不访问宿主 DOM、存储或凭据。

独立视口画布保持原来的 fixed 坐标，只向宿主报告经过有限数值校验的可见控件矩形。宿主裁剪到该区域，避免关闭时一个透明全屏 iframe 挡住聊天。灵感走已有 draft relay，只填输入框，不自动发送。

沿用 `mufySidebarOwnerIndex`：最新完成回复唯一持有；新回复生成期间保留旧持有者，续写冻结同一个挂载实例。火花/记忆侧栏仍由各自共享 CSS 决定渲染，不修改它们的布局契约。
