# Mufy 玩家名称与输入区快捷按钮

2026-11-03。本地验证完成，尚未发布到 8091；整卡验收仍未完成。

产品决策见 [产品记录](../insights/mufy-player-identity-controls.md)。

## 玩家名称

独立来源组件通过 `openingComponentPresentation` 按需加入 `mufy-player-name.ts`。只替换文本节点中的默认玩家标记 `mufyer` 与 `{{user}}`，从既有 Host API 的 `userName` 取当前名称。使用文本替换回调，因此名称中的 HTML 符号、美元符号不会被执行或当替换语法。

WeakMap 保留模板，支持面具切换与作者更新节点；不替换 innerHTML，不重建 details/按钮，不修改属性、脚本、样式和声明为署名的节点。`RegexIframe` 在名称变化时重新握手更新 context，srcDoc 保持不变。来源回复画布与普通平台组件保持旧路径。禁止把整个脏工作区的 RegexIframe 覆盖到测试服：其中另有未经批准的 Bilibili same-origin 改动，必须排除。

## 快捷按钮

实测来源三个按钮为 32×32、间距 6、面板右内缩 10。旧适配器强制独占全宽行，导致宽屏也多一行。`ChatInputToolbar` 保留原工具栏选择器与布局类，按是否有来源控件允许换行；`MufySourceControls` 移到工具栏尾部，快捷面板按自身宽度占位并右对齐。保留原 CSS、影子根和只编辑草稿的行为；固定侧边导航仍固定，不占工具栏流。

本地实际组件预览在 320 / 390 / 768 宽度下无溢出和重叠；四个原生按钮为尺寸占位，不等同完整 ChatRoom 线上验收。当前在 390 下仍需要换行，因为平台比来源多原生控件；不使用负定位强行压在一起。

- 浏览器证据位于批次 `final-acceptance/26/*20261103*`。必须发布后在真实 8091 ChatRoom 和两种宽度复验，再关闭用户缺陷。
