# 第三人称叙事规则强化

> **历史文档：** 2026-08-02 起，旧 `render-protocol.ts` 已被 canonical master + `src/lib/ai/output-protocol.ts` adapter 取代。本文记录的意图仍有效，但修改位置不再有效。

## 背景

用户反馈角色对话中存在 AI 用第一人称"我xxx我xxx"的问题，要求 AI 回复必须站在第三人称视角进行叙事。

## 问题定位

### 根本原因

虽然系统已经使用 `<narration>` 标签来区分"叙述"和"台词"，并在定义中说明是"第三人称叙述"，但**没有明确禁止使用"我"，也没有给出正反面示例**。导致 LLM 在某些场景下可能在 narration 标签内使用第一人称。

### 现有机制

- `<narration>` 标签：用于第三人称叙述
- `<message>` 标签：角色台词（自然会用"我"）
- `<think>` 标签：角色内心独白（第一人称"我"）

问题在于 `<narration>` 和 `<think>` 的人称区别不够明确。

## 解决方案

### 修改位置

`src/lib/ai/render-protocol.ts` 中的 `RENDER_PROTOCOL` 常量。

### 具体修改

#### 1. 增强 `<narration>` 标签说明

**修改前：**
```
<narration>...</narration> 第三人称叙述：**{{char}} 的**动作 / 表情 / 环境 / 肢体细节...
```

**修改后：**
```
<narration>...</narration> **第三人称叙述**：描写 {{char}} 的动作 / 表情 / 环境 / 肢体细节，
以及 {{char}} 对环境的感知。**必须使用第三人称**——用"他"、"她"、"{{char}}"，
绝不用"我"。例如：写"{{char}}皱了皱眉"，不写"我皱了皱眉"；写"他感到一阵不安"，
不写"我感到一阵不安"。
```

**要点：**
- 用粗体强调"必须使用第三人称"
- 给出明确的正反面示例（✅/❌对照）
- 明确禁止使用"我"

#### 2. 明确 `<think>` 与 `<narration>` 的人称区别

**修改前：**
```
<think>...</think> **{{char}}** 第一人称内心独白（与 narration 不同：
                   narration 是叙述者从外部看，think 是你自己在想）
```

**修改后：**
```
<think>...</think> **{{char}}** 第一人称内心独白（与 narration 不同：
                   narration 是叙述者从外部看用第三人称"他/她"，
                   think 是你自己在想用第一人称"我"）
```

**要点：**
- 明确说明 narration 用"他/她"（第三人称）
- 明确说明 think 用"我"（第一人称）

#### 3. 新增独立的第三人称叙事规则

在"规则"部分新增第5条：

```
5. **第三人称叙事规则**：<narration> 标签内必须使用第三人称（"他"/"她"/"{{char}}"），
   绝不使用"我"。只有 <think> 标签内才能用第一人称"我"来表达内心独白
```

**要点：**
- 作为独立规则项，提高权重
- 再次强调 narration/think 的人称区别
- 用粗体标题增强视觉权重

### 为什么这样改有效

1. **三处强化**：标签说明、标签对比、独立规则，三个位置反复强调同一规则
2. **具体示例**：给出了"{{char}}皱了皱眉" vs "我皱了皱眉"的对照，LLM 更容易理解
3. **明确禁止**：用"绝不"这样的强硬词汇，而不是模糊的"应该"
4. **人称对比**：通过 think 和 narration 的对比，让 LLM 明确理解两种标签的人称差异

## 影响范围

### 全局生效

此修改位于 `RENDER_PROTOCOL`，是 host 强制注入的系统 prompt，**对所有角色卡生效**。

### 向后兼容

- ✅ 不影响已有功能
- ✅ 不破坏现有角色卡
- ✅ 只是明确了原本隐含的规则
- ✅ 所有测试通过（243 个测试用例）

### 不受影响的部分

- `<message>` 标签内的台词：角色说话时自然会用"我"，这是正确的
- `<think>` 标签内的内心独白：明确允许用"我"
- 角色卡的 persona 字段：creator 可以继续用任何方式描述角色
